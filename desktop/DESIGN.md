# Desktop companion design

The desktop is a quiet utility for ordinary-media downloads and independent application lifetime. It retains the P02 dark/violet identity with a sparse layout, visible connection state, a media URL form and explicit Quit. A 1px violet rail marks each download; typography and open space carry the hierarchy. P04 adds shared app defaults, revisioned actions and request review; the full manager remains P06.

Design feasibility score: 14 (impact 3, context fit 4, implementation 4, performance 5, consistency risk 2). The scope is a lifecycle window; the full manager remains P06.

Space Grotesk 600 gives the brand/title structure; Source Sans 3 400/600 keeps labels and status readable. Latin WOFF assets ship with the frontend through locked Fontsource packages, so launch does not request remote fonts. Colors are CSS variables in `src/style.css`; spacing follows an 8px rhythm, controls are at least 44px tall and focus is visible. Status changes use semantic live regions, errors use an alert, and progress uses a native progress element. There is no decorative animation.

Missing tray support leaves the window visible. Closing to the tray is enabled only after checking for a Linux StatusNotifierWatcher and successfully creating the tray icon. This check is a capability hint; actual tray behavior still requires the platform validation matrix.

Firefox Flatpak setup is optional help in a native details/summary disclosure above the download form. It keeps the download action visible, supports keyboard activation and wraps the exact browser preference at narrow widths. The preview's temporary add-on is loaded after Firefox restarts. Guidance describes manual browser setup and real desktop permission; app readiness and browser access are distinct. The browser connection section uses ordinary heading, status, definition-list rows and explicit Connect/Repair/Disconnect buttons. It separates registration from browser-granted access and engine readiness. Removing browser access keeps active downloads and history, persists across reopen, and retains visible conflict errors until an explicit action succeeds. The existing dark/violet palette, bundled typefaces and focus/control sizes are inherited.

P04 uses the generated shared session for downloads/defaults and retains native status for tray, installation and browser registration. Download defaults is an inline disclosure with format, folder, template and concurrency fields. Dirty drafts survive external settings changes; stale saves show an explicit conflict and Reload defaults is a deliberate discard/reload action. Bounded download counts, Load more downloads, Cancel/Retry and Check request name their actual actions. Authentication waits show the source URL and direct users to the browser's scoped cookie action. Reconnect updates the view without resubmitting intent. The ordinary-media form states the app format/save location, and narrows to one column without horizontal overflow.

Current P04 renderer evidence is isolated headless Chromium with mocked Tauri delivery and a real non-executing temporary v1 service. Three lifecycle sizes and the 620px/390px migration journey preserve native dialog focus/Escape and unfinished-download removal gating. Actual compiled WebKit/WebView2 and installed-browser acceptance remain open for these changed bytes; prior P02 native GUI evidence remains scoped to its preserved previews.

Installation controls use a separate details/summary disclosure above browser connections. An AppImage can create its own per-user copy and Applications shortcut without interrupting the current session. Ubuntu package removal hands off to App Center. A native HTML dialog protects removal confirmation, initially focuses Keep VidGrab and supports Escape; removal errors stay inside that dialog. Active downloads disable removal, with the engine checking all unfinished database jobs independently of the bounded history list. Paths wrap at narrow widths, and critical action text uses the existing error color. State/media retention and browser disconnection are stated before confirmation.
