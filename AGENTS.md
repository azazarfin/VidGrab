## Mandatory: minimize API calls

- For every task, use the fewest API/tool calls needed to complete the work correctly and safely. Maximize useful work per call; this is mandatory, not a preference.
- Batch independent reads, searches, checks, and edits into a single call whenever supported, using `multi_tool_use.parallel` or `execute` where available. Do not split work into separate calls when it can be combined.
- Reuse gathered context, avoid redundant calls, and never poll background jobs. Make another call only when missing information, a dependent operation, required verification, or a safety check makes it necessary; never skip these requirements just to reduce the count.

## Wiring and state

- Extension code uses classic scripts and the global `vidGrabAPI` from `extension/lib/api.js`, not ES modules. Both manifests are MV3, but Chrome uses `background.service_worker` and Firefox uses `background.scripts`; preserve the browser-specific wiring.
- Detection travels through `video_detected` into bounded document-scoped state and `detected_videos_<tabId>` storage. Shared classic `vidGrabMedia` normalizes candidates; the overlay hands off `pendingVideoCandidate` plus compatible `pendingVideoUrl` without enqueueing. Navigation invalidates stale frame selections/dismissals. Optional request observation defaults off and requires actual webRequest/webNavigation grants. Preserve signed URLs and treat `blob:` as a browser-local hint.
- `backend/app.py:create_app` owns per-app settings, queue/scheduler lifespan, probe cache, cookies and WebSocket connections. `backend/main.py` is the import-safe ASGI adapter. Factory/import performs no database initialization, directory creation, logging configuration or worker startup. Pass `RuntimeConfig(...)` and `start_queue=False` for isolated diagnostics; no `DB_PATH` globals remain.
- P03 selects an owned per-attempt process for ordinary downloads and a joined `asyncio.to_thread` adapter only for explicitly injected diagnostic/test runners. `join_owned_task` defers repeated cancellation until the owned task exits; keep cookie cleanup after that boundary. Windows workers launch detached/suspended, enter the non-inheritable kill-on-close Job Object before their primary thread resumes, and retain explicit pipe/handle whitelists; venv redirectors otherwise can escape containment. Schema-9 claims/terminal writes retain P03 checks and validate the durable owner, expected state and attempt ID; progress carries that ID and commits under per-job locks. Broadcasts cross to the event loop with `asyncio.run_coroutine_threadsafe`. Every engine lifespan, including legacy ASGI and diagnostics, holds `engine-owner.lock` before database initialization. Recovery verifies runtime/worker creation identities and Linux orphan groups before artifact reads/job resets; unknown identities fail closed. A 30-second lease renews every 10 seconds, but expiry never permits replacing a live owner. The P02 owner retains its private Unix IPC/process groups or SID-private pipes/kill-on-close Job Objects and separate app lock. Source/frozen publication/cookie recovery pass. Direct HTTP resume uses an executing-worker identity acknowledgement; Windows checks exact Job membership before replacing a venv launcher identity. Fresh-auth backend handling, static clear fragment resume and bounded playlist children/idempotent enqueue are implemented; persisted retry/request budgets now bound normal HTTP(S) requests; read ADR-023 for the selected urllib-only lane and limits.
